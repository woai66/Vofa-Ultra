# 安全命令模板

命令模板用于给手动发送、周期发送、快捷命令和自动应答加入可预测的序号与时间字段。它只做一次白名单变量替换，
不执行 JavaScript、Wasm、Shell 或用户表达式，也不读取环境、文件、网络、接收数据和通道状态。

## TEXT 变量

| 变量 | 输出 |
| --- | --- |
| `${seq}` | 从 1 开始的十进制发送序号 |
| `${unix_ms}` | 本次派发的 Unix 毫秒整数 |
| `${unix_s}` | 本次派发的 Unix 秒整数，向下取整 |
| `${iso_utc}` | 本次派发时间的 ISO-8601 UTC 文本 |
| `${task_unix_ms}` | 周期任务或自动应答会话启动时冻结的 Unix 毫秒整数 |

TEXT 中 `$$` 输出一个字面量 `$`，因此 `$${seq}` 会发送 `${seq}`，不会再次解释变量。

```text
SET,channel=2,sequence=${seq},time=${unix_ms}
```

## HEX 变量

HEX 变量必须显式声明宽度和端序。变量直接产生字节，不会先转成文本再交给 HEX 解析器。

| 变量 | 可用格式 |
| --- | --- |
| `seq` | `u8`、`u16le`、`u16be`、`u32le`、`u32be` |
| `unix_ms` | `u64le`、`u64be` |
| `unix_s` | `u32le`、`u32be`、`u64le`、`u64be` |
| `task_unix_ms` | `u64le`、`u64be` |

例如序号 1 的 `${seq:u16le}` 输出 `01 00`，`${seq:u16be}` 输出 `00 01`。

```text
AA 55 ${seq:u16le} ${unix_ms:u64be} 0D 0A
```

变量两侧的 HEX 字面量分别由现有 HEX 解析器校验，必须各自落在完整字节边界。`A${seq:u8}` 和
`${seq:u8}B` 都会被拒绝；不会猜测半字节应该如何拼接。`iso_utc` 没有二进制定宽格式。

## 发送校验尾

发送栏的工作区级校验模式支持“无”、CRC-16/MODBUS 低/高字节在前、CRC-32 低/高字节在前、XOR-8 和
SUM-8。它不是模板表达式，而是模板展开后的固定构帧阶段：

```text
展开后的 payload -> 原始校验字节 -> TX 行尾
```

CRC、XOR 与 SUM 只覆盖展开后的 payload，不包含自身校验字节或行尾。CRC-16 与 CRC-32 分别追加 2 和 4 个字节，
XOR-8 与 SUM-8 追加 1 个字节；选择的 LE/BE 只改变多字节校验值在线路上的排列。payload、校验尾和行尾组成的
完整帧仍受 64 KiB 单次发送上限约束，超限时不产生 TX 或历史。
空原文可以搭配 LF、CR 或 CRLF 周期发送；空原文加无行尾仍因最终字节为空而拒绝。

该设置随工作区保存，手动发送读取当前值，周期任务在启动时冻结当次值。快捷命令不保存校验模式，载入后使用
当前工作区设置；命令历史则保存并恢复实际使用的模式。自动应答、Modbus 事务和原始文件发送有各自的构帧边界，
不会继承此设置。Modbus 构帧器回填已经包含 CRC 的 ADU 时会主动切换为“无”，避免重复追加。

## 调度与历史语义

- 手动发送始终使用 `seq = 1`，本次时间同时作为 `unix_ms` 和 `task_unix_ms` 的上下文。
- 周期任务启动时冻结原始模板、格式、校验模式、行尾和 `task_unix_ms`，之后编辑输入框不会改变运行任务。
- 周期任务第一次立即使用序号 1；每次成功发送后才推进序号，失败不跳号、不重试、不追赶遗漏周期。
- `unix_ms`、`unix_s` 和 `iso_utc` 在每次派发时共享同一次时间采样。
- 每轮先展开 payload，再按冻结模式计算校验尾，最后追加行尾；三部分共同计入最终发送字节上限。
- 历史保存原始模板与校验模式；点击历史后恢复模式并重新求值。含变量条目显示最近一次展开长度，实际字节以 TX
  终端和 VUCAP 为准。连续项的去重比较也包含校验模式。
- 编译、渲染或发送失败都不会写入历史；周期任务的后续渲染失败会保留已有成功计数并进入错误终态。

## 工作区快捷命令

快捷命令保存名称、原始模板、TEXT/HEX 格式和行尾，不保存展开结果或校验模式。点击条目只把这些字段载入发送草稿；
不会计算变量、调用发送 API、生成 TX、写入历史或启动周期任务。用户显式发送时使用当前工作区的校验模式，仍走
本页相同的编译、渲染、校验、行尾、仲裁和 64 KiB 最终字节门禁。

每个工作区最多 32 条，名称为 1 到 64 个无控制字符文本，全部原始模板按 UTF-8 合计最多 128 KiB。ID 必须唯一，
数组顺序就是显示、持久化和导出顺序。模板原文不会 trim 或格式化；空原文仅能与 LF/CR/CRLF 组成非空命令，空原文
加无行尾会被拒绝。严格解析同样拒绝未知字段、非法 HEX 和未知变量。

快捷命令随当前工作区 schema 保存在本机状态和导出 JSON 中，不进入串口诊断。模板可能包含密码、令牌或设备业务数据；
保存和分享工作区文件前应按持久化敏感数据处理。删除本机条目不会清除已经导出的副本。

## RX 自动应答

自动应答是独立于协议解析器的实时字节状态机，不把 RX、通道值或表达式加入模板语言。最多 16 条规则按列表顺序
匹配；触发器只接受 UTF-8 TEXT 或静态 HEX 字节串，单条最多 256 字节。HEX 源文本最多 4 KiB，保存时规范化为
`AA BB`。匹配发生在原始实时 RX 上，支持跨接收 chunk、重叠模式和 `00` 字节；VUCAP 回放使用独立入口，永远
不会触发应答。

响应复用本页的安全命令模板和规则自身的行尾编码，不读取发送栏的工作区校验模式。单条原始响应模板最多 4 KiB。
`${seq}` 从当前自动应答会话的 1 开始，
只有进入有界 FIFO 的应答才占用序号；自动 TX 继续进入终端、统计和 VUCAP，但不写入手动命令历史。每条规则有
独立的 20 ms 到 24 小时整数冷却，命中时间由接收批次时间单调化，不承诺硬实时或确定性响应延迟。

运行时使用最多 32 个含在途项的全局 FIFO，并且只允许一次物理写入。手动发送会等待当前自动写入完成，然后优先于
其余自动队列；周期发送与自动应答严格互斥。单批最多处理 64 次匹配，单个 RX 批次最多 64 KiB，每次启用最多接受
1,000 个应答。队列溢出、匹配预算超限、渲染或发送失败都会清空待发送项并进入可见错误终态，不静默丢弃。

规则随当前工作区 schema 保存；启用态、匹配尾、冷却时间点、队列、计数和错误仅属于当前应用会话，默认关闭。断连、
换源、换协议、串口重连的新流边界、切换工作区、进入回放或运行时卸载都会停机且不会自动恢复。设备回显仍可能
构成逻辑环路，因此冷却、队列和会话上限是强制安全边界，不能关闭。

## 资源与安全边界

| 边界 | 上限 |
| --- | ---: |
| 原始模板 UTF-8 长度 | 256 KiB |
| 单个模板变量数量 | 256 |
| 单个变量 token 长度 | 64 个 UTF-16 code unit |
| 展开 payload、校验尾与行尾合计 | 64 KiB |
| 快捷命令 | 每个工作区 32 条 |
| 快捷命令名称 | 64 个字符 |
| 快捷命令原始模板合计 | 128 KiB UTF-8 |
| 自动应答规则 | 16 条 |
| 自动触发串 | 每条 256 字节 |
| 自动响应模板 | 每条 4 KiB |
| 自动应答 FIFO | 含在途项共 32 条 |
| 自动应答会话 | 1,000 次 |

扫描器只接受 `${name}` 或 `${name:format}`。未知名称、未知格式、空白、点属性、函数调用、运算符、多冒号、
未闭合或嵌套 token 都会报错。无符号整数在写入定宽字段前核对范围，禁止截断和回绕。

模板语言明确不支持用户自定义变量、算术、条件、循环、函数、随机数、UUID、CRC 表达式、端口或环境字段、RX /
波形 / 通道引用和递归展开。自动校验尾是上述固定构帧阶段，自动应答则通过独立字节状态机实现；两者都不改变
扫描器语法。其他能力需要各自的威胁模型、权限边界和任务协议。

## 实现与验证

模板与自动校验纯函数实现位于 `src/core/commandTemplate.ts` 和 `src/core/checksum.ts`，快捷命令严格解析位于
`src/core/quickCommands.ts`，周期调度位于
`src/core/commandWorkflow.ts`，自动应答与发送仲裁位于 `src/core/autoResponder.ts`。Store 只把最终
`Uint8Array` 交给模拟器或 Rust 串口层，后端继续执行权威的 64 KiB 单次发送上限，不解析模板。

修改变量、格式或校验模式时，至少运行 `pnpm check` 和 `pnpm test:e2e`，并补齐 TEXT、HEX 大小端、校验标准向量、
构帧顺序、错误输入、大小边界、序号成功后推进、时间采样、历史与零发送失败路径。自动应答还必须覆盖跨 chunk、
重叠、NUL、冷却、所有硬上限、手动优先、回放旁路、失败停机与工作区迁移。
