# 兼容性与弃用政策

本文定义 Vofa-Ultra 对已发布配置、捕获文件和协议标识的兼容承诺。根目录
[`compatibility-policy.json`](../compatibility-policy.json) 是供测试和工具读取的当前支持矩阵；本文解释其语义。
两者不一致时视为发布阻断，不能只修改文档或只放宽 reader。
当前机器清单自身为 schema v2；v2 将实验性扩展 ABI 从单一状态值改为结构化版本契约。

## 当前支持矩阵

| 数据面 | 当前写入 | 当前读取/迁移 | 遇到未来版本 |
| --- | --- | --- | --- |
| 工作区 JSON `vofa-ultra.workspace` | v8 | 严格读取 v1-v8，导入后归一为 v8 | 拒绝导入，不猜测字段含义 |
| 本地工作台状态 `vofa-ultra-workbench` | v8 | 从 v0-v7 迁移；v8 直接恢复 | 保留原值并进入只读保护，禁止覆盖 |
| VUCAP 捕获文件 | v2 | 流式读取 v1/v2 | 明确拒绝，不按当前版本猜测 |
| 协议 wire ID | `firewater`、`justfloat`、`raw` | 已发布 ID 永久保持原含义 | 旧客户端明确拒绝未知 ID |
| `.vux` Wasm 扩展 | packer 写 schema/API v1 | 桌面端只读 v1；状态为 experimental | 明确拒绝未知 schema/API |

“读取旧版本”只承诺新版本应用能读取矩阵中的历史格式，不承诺旧版本应用能读取新格式。工作区导入失败不会
创建或覆盖命名工作区；未来版本的本地状态不会被当前应用写回。VUCAP 文件缺少 footer 或尾部被截断时，reader
可以使用已验证的完整条目前缀，这属于损坏恢复，不会改变版本兼容规则。

本地状态是应用恢复数据，不是跨设备交换格式。需要备份、迁移或提交 Issue 时，应导出工作区 JSON；不要依赖
浏览器或 WebView 的 `localStorage` 文件位置。

工作区 v8 增加 `terminalRxTextEncoding`，只允许 `utf-8`、`gb18030` 和 `windows-1252`。严格的 v1-v7 文件
迁移时补为 `utf-8`；导入后统一写为 v8。高于 v8 的工作区仍拒绝导入，本地状态仍保留原值并进入只读保护。

工作区 v7 增加 `terminalRxRecordMode` 和 `terminalRxLineEnding`，分别保存终端 RX 按读取块/文本行记录的方式与
文本行使用的 LF/CRLF/CR 分隔符。严格的 v1-v6 文件迁移时补为 `chunk` 和 `lf`，保持旧版本每个读取块一条
记录的行为；迁移到 v8 后仍保留该选择。

工作区 v6 在顶层发送配置、自动应答和快捷命令的行尾枚举中新增 `cr`，表示只追加单字节 `0D`。严格的 v1-v5
reader 仍只接受 `none`、`lf` 和 `crlf`，不会把新值倒灌到历史 schema；迁移到 v8 后继续保留 v6 的 CR-only
语义。

工作区 v5 在 v4 基础上增加命名快捷命令。每条命令保存稳定 ID、名称、原始模板、TEXT/HEX 模式和行尾；数组
顺序就是用户排序。严格 v1-v4 文件迁移后得到空快捷命令列表，不会从会话命令历史推断或复制内容。本地 v4
迁移保留全部命名工作区并为每个快照补充空列表。工作区 JSON 上限为 2 MiB，覆盖自动应答与快捷命令达到资源
上限且控制字符采用最坏 JSON 转义时的往返需求。

## 稳定边界

以下内容属于公开兼容边界：

- 工作区格式标识、schema 版本及已发布版本的读取语义。
- VUCAP magic、版本、条目语义及已发布版本的读取语义。
- `protocol` wire ID 的身份和含义。ID 只能追加，不能改名、删除、复用或静默改义。
- `docs/protocols.md` 中对内置 parser 的分包、资源上限、恢复、健康度和 seek 行为要求。

新增协议必须同时更新前端注册表、Rust 捕获白名单、机器清单、格式文档和跨层测试。旧版本拒绝新协议 ID 是
允许的前向不兼容；新版本不得把未知 ID 降级为 Raw，也不得让旧 ID 指向另一种编码。

以下内容目前不构成稳定第三方 API 或 ABI：

- `src/` 下的 TypeScript 类型、模块路径、React 组件和 Zustand store 结构。
- Tauri command、事件 payload 和 Rust 内部模块边界，除非另有版本化 wire 文档。
- 实验性 `vux-wasm-v1` 的具体 ABI、包字段和行为；它已经提供，但尚不享受稳定数据面的弃用期限。
- JavaScript 插件、原生动态库、UI 注入、WASI、回放 parser 和内置协议的运行时注册；这些能力未提供。
- 未列入 `compatibility-policy.json` 的内部缓存、会话状态和测试夹具。

机器清单对实验性 ABI 使用结构化记录：标识、状态、包格式、schema/API 版本和未来版本行为。它用于防止实现、
Schema、工具和文档漂移，不把 experimental 提升为稳定承诺。仓库内协议贡献契约可以随源码一起演进，但变更
必须在同一 PR 中更新实现和夹具；它不允许仓库外代码注入主 WebView。

## 版本规则

项目遵循 SemVer。虽然 `0.x` 的 minor 版本在 SemVer 中可以包含破坏性变化，Vofa-Ultra 对上述稳定数据面采用
更严格规则：已进入机器清单的读取版本不会仅因 `0.x` minor 升级而移除。

兼容变更包括：

- 在新 schema 或新捕获版本中增加能力，同时保留旧 reader。
- 追加新的协议 wire ID，并让未知 ID 继续确定失败。
- 修复 reader 对无效输入的拒绝，使此前未被文档允许的文件不再误读。
- 增加可选 UI 或内部字段，但不改变已发布 wire 含义。

破坏性变更包括：

- 移除清单中的读取/迁移版本，或把旧数据迁移为不同含义。
- 复用、重命名或删除协议 wire ID。
- 不提升格式版本便改变字段、字节、时间或条目语义。
- 把明确拒绝未来版本改为静默回退、丢字段或覆盖原数据。

写入格式升级必须先有 reader、边界测试和迁移说明，再切换 writer；不能先产生当前稳定版无法验证的新文件。
`compatibility-policy.json` 自身结构发生不兼容变化时必须提升其 `schemaVersion`。

实验性 `.vux` 变更仍必须更新 identifier/schema/API、JSON Schema、packer/verifier、真实运行时示例、
`CHANGELOG.md` 和安全文档。预发布版本可以拒绝旧 experimental 包且不承诺转换器，但必须确定失败，不能把旧字段
静默解释为新含义。只有明确转为 stable 后，才适用本文 90 天/两个 minor 的最低弃用期。

## 弃用与移除

对稳定边界的弃用必须同时满足：

1. 在 `CHANGELOG.md`、相关格式文档和发布说明中标记弃用，说明受影响版本、替代方案和数据风险。
2. 提供无损迁移路径、只读 reader 或独立转换工具；不能要求用户静默丢弃既有数据。
3. 在至少两个已发布 minor 版本且至少 90 天内继续支持，以时间更长者为准。
4. 只有 major 版本可以移除读取能力，并由独立 reviewer 核对迁移证据和机器清单变化。

协议 wire ID 即使停止用于新建配置也不得复用。若因安全或数据完整性问题必须提前禁用某种输入，发布说明和
安全公告必须解释原因，reader 应确定失败并保留原文件，不能把不可信内容解释成另一协议。

## 变更门禁

涉及配置、捕获格式、协议持久标识或实验性扩展 ABI 的 PR 必须：

- 更新 `compatibility-policy.json`、本文、对应格式文档和 `CHANGELOG.md`，或明确说明为何兼容矩阵未变。
- 覆盖当前 writer、全部声明可读版本、未来版本拒绝/保护，以及协议 ID 前后端一致性。
- 运行 `pnpm check` 和完整 Rust fmt、Clippy、test；发布候选还需执行打包与端到端门禁。
- 在 PR 的“需重点 review”中逐项说明向后读取、旧版前向读取、回滚和数据丢失风险。

前端测试直接核对工作区、本地状态和协议 ID；Rust 捕获测试核对 VUCAP 与内置协议白名单，扩展运行时测试则用
实现常量直接核对 `.vux` 包格式、schema/API 版本和 experimental 状态。修改清单而未同步实现会令门禁失败。

## 不在本承诺内

本政策不证明安装包签名、公证、可复现构建、特定操作系统或 USB 串口芯片兼容，也不替代真实硬件验证。
实验性 Wasm 扩展的解释器限制和会话授权不等于 OS 进程沙箱、发布者认证或完整插件生态；在威胁模型、真实使用
证据、迁移策略和签名来源完成前，不会宣称存在稳定插件 API。细节见[扩展契约](extensions.md)。
