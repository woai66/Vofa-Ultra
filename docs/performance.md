# 性能基准

性能门禁用于阻止协议解析、处理图和工作台数据平面的数量级回退，不用于比较开发者硬件。GitHub Actions 的
Ubuntu 22.04 performance job 是绝对预算的权威环境；Windows、macOS 和其他本地结果只用于定位变化。

## 运行与产物

```bash
pnpm benchmark
```

命令固定使用一个 Vitest worker，并禁用文件并行。原始报告写入 `artifacts/performance/vitest.json`，校验后的
机器可读摘要和 Markdown 摘要分别写入 `summary.json`、`summary.md`。该目录是诊断产物，不提交到仓库；CI 无论
成功或失败都会上传 14 天。

## 固定场景

| 场景 | 固定工作量 | 主要边界 |
| --- | ---: | --- |
| FireWater 分片解析 | 1 MiB | 4093 字节非对齐分片、完整帧计数 |
| JustFloat 分片解析 | 1 MiB | 4093 字节非对齐分片、完整帧计数 |
| 处理图 | 4096 帧、20 节点 | 编译后运行时和输出计数 |
| 实时 Store | 16400 字节、4 通道 | 2000 点饱和缓冲、Base64 解码、真实串口事件入口 |
| 回放 Store | 64 条记录、192 帧 | 2000 点饱和缓冲、多记录解析、ACK 边界 |

每个任务预热至少 300 ms 和 5 次迭代，再测量至少 1000 ms 和 15 次迭代。Store 的预填不计入样本，正式迭代
始终保持缓冲饱和。场景函数同时断言帧数、字节数、通道上限和终端记录，防止用少做工作换取更快结果。

## 预算维护

`performance-budgets.json` 是严格清单：报告缺少场景、出现未预算场景、样本不足或中位数超过上限都会失败。
当前上限综合了业务吞吐目标和同一 Windows 环境五轮校准结果，并为 Linux runner 与后台噪声保留明显余量。

修改工作量、场景名或预算时，PR 必须同时更新基准、预算、校验器测试和本文。放宽上限还必须提供同一环境至少
五轮独立运行的中位数、RME、样本数、机器与 Node 版本，说明业务吞吐依据，并由性能退化修复之外的 reviewer
确认。不要在实现变慢时直接抬高预算；先用报告定位算法复杂度、分配量和不必要的状态物化。
