# 故障排查矩阵

先记录界面右上角版本、运行模式、操作系统和复现步骤。涉及真实串口时，再记录适配器芯片、驱动、VID/PID 和
完整串口参数，但不要公开 USB 序列号、业务载荷、密钥或用户绝对路径。

## 快速隔离

1. 在浏览器预览启动模拟器。若模拟器也失败，优先检查应用、协议或界面状态。
2. 若模拟器正常而真实串口失败，关闭其他串口工具，重新枚举设备并核对驱动与参数。
3. 先看终端原始 RX，再看“通道”的解析健康度；不要用“没有波形”直接推断串口没有数据。
4. 文件任务失败时保留原 `.vucap`、`.part` 和界面错误，不要反复覆盖同一目标。

## 常见问题

| 症状 | 常见原因 | 处理 |
| --- | --- | --- |
| “串口”按钮禁用 | 当前是浏览器预览 | 使用桌面应用；浏览器只支持模拟器 |
| 串口列表为空 | 未刷新、驱动缺失、设备未枚举 | 重插设备、刷新列表，在系统设备管理器确认驱动 |
| 保存的端口显示“当前不可用” | 端口名变化或设备离线 | 刷新并重新选择；不要仅凭旧端口名判断设备身份 |
| 连接立即失败 | 端口被占用或参数/权限错误 | 关闭其他串口程序，核对参数与系统权限后重试 |
| 一直“正在打开” | 驱动打开阻塞 | 点击取消，拔插设备；保留诊断后检查驱动 |
| 终端有乱码 | 波特率、数据位、校验或编码不匹配 | 先核对串口参数；用 HEX 判断实际字节 |
| 终端计数有值但列表为空 | 搜索内容或 RX/TX 方向没有命中 | 清空搜索并切回“全部”；切换 TEXT/HEX 会重新匹配 |
| 有 RX 但没有波形 | 选择 Raw、协议选错或帧未完成 | 切换正确协议，查看解析健康度和帧边界 |
| “等待完整帧”不结束 | FireWater 无 LF 或 JustFloat 无完整帧尾 | 修正发送端分帧；用 HEX 检查终止字节 |
| 解析持续丢帧 | 超长、通道过多、格式/标签/有限值错误 | 查看最近原因，按协议约束修正设备输出 |
| “扩展”不能选择包 | 当前是浏览器预览 | 使用桌面应用；浏览器不加载本地 `.vux` |
| `.vux` 检查失败 | Schema/API、摘要、Wasm ABI/import/start 或资源边界不符合 v1 | 保留原包和 SHA-256，使用 `pnpm extension:verify` 后修复发布端 |
| 扩展“启用”按钮禁用 | 未连接实时来源、仍在回放或未勾选本次授权 | 关闭回放、连接来源，审查包后显式授权 |
| 扩展运行后自动停用 | fuel、内存、ABI、输出 JSON、队列或宿主运行时故障 | 先看稳定故障码；基础串口链路仍会继续，修复 guest 后重新选择 |
| 扩展没有波形 | guest 正在等待半帧、返回空帧、通道隐藏或波形暂停 | 检查扩展计数/队列并重置；扩展不会修改基础协议健康度 |
| 发送按钮禁用 | 未连接、发送在途或运行事务中 | 等待当前操作完成并确认状态栏已连接 |
| HEX 发送被拒绝 | 非法字符、半字节或变量未定宽 | 使用完整十六进制字节；给 HEX 变量指定格式 |
| Modbus“填入发送框”禁用 | 站号/地址/数量/值非法，或范围越过 65535 | 从面板首个错误修正；地址使用 0-based 原始值 |
| Modbus 写广播后无 RX | 站号 0 表示广播，规范上没有响应 | 需要响应时改用 1-247 单播站号并核对设备地址 |
| 周期发送停止 | 断连、换源、队列满或模板渲染失败 | 修复界面显示的首个错误，再显式新建任务 |
| 自动应答未触发 | 未启动、规则禁用、回放输入或字节不匹配 | 检查规则顺序/格式；仅实时 RX 会触发 |
| 自动应答停机 | 队列、单批匹配或会话上限触发 | 排除回显环路，增加冷却，再手动重启 |
| 自动重连处于阻塞 | 缺 VID/PID/唯一序列号或出现多个候选 | 手动选择设备；应用不会按端口名猜测 |
| 自动重连停止 | 录制收尾失败或十次重试耗尽 | 先处理文件/设备问题，再手动连接 |
| 录制按钮不可用 | 浏览器、未连接或回放仍打开 | 使用桌面端，连接来源或先关闭回放 |
| 录制留下不完整文件 | 磁盘、队列、进程或设备故障 | 保留文件；回放/导出仅使用已验证前缀 |
| 数值记录不可用 | Raw、浏览器或未连接 | 选择 FireWater/JustFloat 并使用桌面端 |
| 回放拒绝文件 | magic/版本/结构损坏或尚在录制 | 不修改源文件；保存错误和文件哈希后报告 |
| 回放显示“尾部不完整” | 缺 footer 或尾部截断 | 可回放有效前缀；不要把它当作完整捕获 |
| 时间轴不能拖动 | 正在播放/定位或协议不支持 | 先暂停；等待当前定位结束 |
| 定位位置向后跳 | 结构化协议吸附到下一安全同步点 | 这是预期行为；以界面返回的实际位置为准 |
| BIN 双向选项禁用 | 裸字节流无法保存方向 | 选择仅 RX/仅 TX，或改用 CSV/JSONL |
| 导出不能取消 | 已进入提交阶段 | 等待原子替换完成；不要终止进程 |
| 工作区进入只读模式 | 本地数据来自更高版本 | 保留原数据并升级应用；当前版本禁止覆盖 |
| 工作区导入失败 | 超过 2 MiB、未知字段或版本/引用无效 | 使用原导出文件，按错误修复生成端而非手改猜测 |
| 处理图无法启用 | 重复 ID、未知引用、循环或参数越界 | 从首个错误节点开始修正拓扑和参数 |
| 处理图显示已暂停 | 预算熔断或运行时异常 | 基础链路仍工作；降低复杂度后点击“重试处理图” |
| “姿态映射未完成” | 必需通道未映射 | 配置 Euler 三轴或 Quaternion 四元数通道 |
| 一直“等待完整姿态帧” | 映射值不在同一完整帧或四元数无效 | 让发送端在同一帧输出全部有限值 |
| “3D 渲染不可用” | WebGL/显卡驱动或远程桌面限制 | 更新驱动，关闭 GPU 覆盖层；数值读数仍可用 |
| 安装或首次启动被系统拦截 | 当前候选包未签名/未公证 | 只使用可信构建并核对 SHA-256；不要关闭全局安全策略 |

## 串口错误码

诊断中的稳定错误码用于分类，不包含可能泄密的原始系统错误：

| 错误码 | 含义 | 优先检查 |
| --- | --- | --- |
| `invalid-config` | 串口配置在打开前无效 | 端口名、波特率、数据位、校验、停止位、流控 |
| `open-failed` | 系统无法打开端口 | 占用、权限、驱动、设备在线状态 |
| `dtr-failed` | 打开后设置 DTR 失败 | 驱动、适配器能力、目标复位行为 |
| `rts-failed` | 打开后设置 RTS 失败 | 驱动、硬件流控和适配器能力 |
| `worker-start-failed` | 串口 worker 未能启动 | 系统资源、驱动异常、应用日志 |
| `read-failed` | 已连接端口读取失败 | 拔插、线缆、电源、驱动 |
| `write-failed` | 已连接端口写入失败 | 拔插、流控、驱动、目标接收状态 |
| `worker-panic` | worker 非正常退出 | 保留版本、步骤和诊断，提交缺陷 |
| `unknown` | 未分类错误 | 提交最小复现和脱敏诊断 |

## 没有波形时

按以下顺序检查，避免跳过原始数据层：

1. 状态栏是否显示已连接，RX 字节是否增长。
2. 终端 HEX 是否出现预期字节；若没有，检查设备、线缆、参数和流控。
3. 是否误选 Raw；Raw 设计上不产生波形。
4. FireWater 是否以 LF 结束，JustFloat 是否包含完整小端 float32 和帧尾。
5. “通道”是否出现丢弃原因，通道是否被隐藏。
6. 处理图只影响派生通道；关闭处理图确认基础通道。
7. 回放时确认文件协议与数据内容一致，并在 seek 后等待下一个安全同步点。

## 文件失败时

- 不要用文本编辑器保存 `.vucap`，也不要覆盖源文件。
- 记录源文件大小、SHA-256、界面显示的格式版本和完整性状态。
- `.part`、无 footer 或尾部截断不等于全部数据不可用；只信任应用验证过的前缀。
- 未来版本错误需要升级 reader，不能把版本字节改成当前值。
- 导出失败时保留源文件；目标临时文件不应被当作成功结果。

## 性能或界面卡顿

1. 停止模拟器/串口后观察卡顿是否立即消失，区分数据吞吐与系统问题。
2. 切换回“波形”视图，检查 WebGL 或远程桌面 GPU 路径。
3. 暂停波形只停止显示追加，不会停止解析/录制；要隔离输入负载需断开数据源。
4. 检查是否有多个开发服务器、浏览器自动化或调试插件后台实例。
5. 记录任务管理器中的进程/线程、提交内存和上下文切换，而不只看总 CPU。

不要为了排障扩大缓存、关闭 CSP、禁用系统安全策略或把未知协议降级为 Raw。

`.vux` 的包 SHA-256 只用于完整性和检查后绑定，不代表发布者可信。不要通过关闭安全策略或修改 manifest 来绕过
拒绝；完整边界见[实验性 Wasm 扩展](extensions.md)。

## 提交可复现报告

提交 Issue 前准备：

- Vofa-Ultra 版本或 commit、安装包类型、操作系统版本和架构。
- 浏览器预览或桌面模式；真实硬件填写芯片/板卡、驱动和 VID/PID。
- 完整串口参数、协议、固件/测试夹具版本、最小复现步骤和期望/实际结果。
- 出现次数、持续时间、速率，以及是否涉及拔插、重连、录制、回放或导出。
- 应用导出的串口诊断、必要截图和文件 SHA-256；先按[安全策略](../SECURITY.md)脱敏。

真实硬件结果请遵循[硬件兼容性清单](hardware-compatibility.md)中的证据格式，并使用
[硬件兼容性报告表单](../.github/ISSUE_TEMPLATE/hardware_report.yml)。涉及漏洞或敏感数据泄露时，不要创建
公开 Issue，按安全策略私密报告。
