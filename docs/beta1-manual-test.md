## 测试目标

本轮人工测试要回答八个问题：

1. 安装包能否在普通 Windows 用户环境中安全安装、启动、退出、卸载和重装。
2. 串口能否可靠枚举、连接、断开、重复连接，并正确处理占用和热插拔。
3. TEXT、HEX、编码和行尾是否按原始字节准确收发，不静默修改数据。
4. FireWater、JustFloat 和 Raw Data 是否严格遵守各自边界。
5. 常见操作是否顺手，窗口变化后是否仍无重叠、遮挡、跳动或不可达控件。
6. 终端、波形、监视、录制、回放和导出的结果能否相互核对。
7. 错误是否明确、可恢复，诊断是否脱敏。
8. 持续运行时是否无明显卡顿、失控增长、丢帧或文件损坏。

## 优先级与放行规则

| 优先级 | 用途 | 建议 |
| --- | --- | --- |
| P0 | 首轮必测，约 90–120 分钟 | 先完成；任一稳定失败都应暂停 Beta 发布并修复 |
| P1 | 完整 Beta 核心验收，约 3–5 小时 | 在 P0 通过后分批完成；核心项稳定失败会阻塞发布 |
| P2 | 兼容性扩展、特殊夹具、长稳或冻结功能 | 不阻塞首个 Beta；只约束对应兼容性声明 |

首个公开 Beta 前，至少要用一套真实开发板或 USB 串口设备完成 P0，以及与该设备能力相符的 P1 核心项，并留下
可复核的硬件、驱动、速率、时长和错误计数。P2 未测试不会阻塞首个 Beta，但不能据此宣称对应芯片、高波特率、
流控或控制线已经兼容；扩大兼容声明时再补足两种芯片、专用夹具和长稳证据。

## 测试准备

- Windows 10 或 Windows 11 x64 电脑，不需要关闭 Windows 全局安全策略。
- 一块能修改固件的 STM32、ESP32 或其他开发板，或者具备回环能力的 USB 转串口适配器。
- 一根已确认支持数据传输的 USB 线。
- 一个可用于核对设备端实际收发字节的方式，例如设备日志、调试器、逻辑分析仪或第二个已知正常的串口工具。
- 测试前退出可能占用同一端口的软件；`SER-04` 除外，该项会故意制造端口占用。
- 建议新建空目录保存 `.log`、`.vucap`、`.csv`、`.jsonl` 和 `.bin` 证据。

建议测试固件至少能完成以下一种或多种行为：

- 周期发送 `VOFA-ULTRA-RX-001\r\n`。
- 收到 `PING\r\n` 后返回 `PONG\r\n`。
- 原样回显收到的字节，用于验证 `00 01 7F 80 FF`。
- 周期发送 FireWater 帧 `1.0,2.0,3.0\n`。
- 周期发送小端 `float32` 的 `1.0, 2.0, 3.0`，随后追加帧尾 `00 00 80 7F`。
