# 硬件兼容性清单

本清单只记录可复核的真实设备测试，不依据底层库支持列表、CI 编译成功或相似芯片推断兼容。截至
2026-08-25，仓库尚未收录满足下述证据门槛的真实串口设备记录，因此当前“已验证设备”列表为空。

这不表示设备不兼容，只表示项目还没有可公开审计的实测证据。浏览器模拟器、桌面桥接 mock 和自动测试都不能
替代真实 USB 串口、驱动、线缆和目标固件测试。

每份报告绑定一个具体设备和测试环境。新结果使用
[硬件兼容性报告表单](../.github/ISSUE_TEMPLATE/hardware_report.yml)，维护者复核后再更新本清单。

## 首轮 Beta 快速测试

这份快速清单用于维护者拿到候选安装包后的第一轮试用，预计 20–30 分钟。它的目标是尽快发现阻塞使用的问题，
不要求一次完成后文的兼容性认证，也不要因为某项没有测试条件而猜测通过。

需要按编号逐项执行、记录通过标准和失败证据时，请使用
[Vofa-Ultra 0.1.0-beta.1 Windows 人工测试单](beta1-manual-test.md)。本节只保留快速冒烟摘要。

### 准备

- Windows 10 或 Windows 11 x64，以及本轮提供的 NSIS `.exe` 候选安装包。
- 一块 STM32、ESP32 或其他能稳定收发串口数据的开发板，或一个已知正常的 USB 转串口适配器。
- 一根确认支持数据传输的 USB 线，并关闭其他可能占用该端口的串口软件。
- 记录应用版本或 commit、Windows 版本、开发板或串口芯片、驱动版本和串口参数；不要记录完整 USB 序列号。

### 操作清单

- [ ] 安装并启动：安装过程无异常，应用能进入主界面。未签名候选包可能触发 Windows 警告，但不应要求关闭
      系统全局安全策略。
- [ ] 枚举与连接：设备插入后能出现在列表中；使用正确参数连接、断开并重新连接 3 次，状态和按钮均恢复正常。
- [ ] 基础接收：开发板连续发送已知文本，终端显示的内容、方向和字节数正确；TEXT 与 HEX 显示可相互核对。
- [ ] 基础发送：分别发送一条已知 TEXT 命令和 `00 01 7F 80 FF` HEX 字节，对端收到的字节与输入完全一致。
- [ ] 文本选项：按固件能力检查 LF、CR 或 CRLF 行尾；需要中文时，再检查 UTF-8 或 GB18030 收发。没有对应
      固件能力的编码不标记通过。
- [ ] FireWater 波形：让设备持续发送 `1.0,2.0,3.0\n` 一类数值帧，确认通道出现、曲线持续更新，暂停、继续、
      时间窗切换、缩放和“回到实时波形”可正常使用。
- [ ] JustFloat 波形：若固件支持，以小端 `float32` 加 `00 00 80 7F` 帧尾发送 1–16 个通道，检查数值和通道数；
      没有对应固件时记录为“未测试”。
- [ ] Raw Data：发送包含 `00` 和非 ASCII 字节的数据，确认 HEX 终端没有丢字节。当前候选包的 Raw Data 只用于
      原始终端，不生成波形，因此 Raw 不作为本轮波形验收项。
- [ ] 拔插恢复：连接期间拔出设备，应用应明确显示断开且界面不冻结；重新插入后可再次枚举并连接。设备具有
      唯一 USB 身份时，再检查自动重连与取消。
- [ ] 保存与导出：导出一次终端日志；FireWater 或 JustFloat 有数值通道时，再完成一次短时记录、停止和文件打开。
- [ ] 卸载与重装：退出应用后从 Windows“已安装的应用”卸载，确认进程、应用目录和快捷方式不再存在，然后重新
      安装并启动一次。

## 状态定义

| 状态 | 含义 |
| --- | --- |
| 已验证 | 指定系统/驱动/应用版本下，声明的每一项都有可复核证据 |
| 部分验证 | 基础收发通过，但拔插、流控、控制线、长稳或其他声明项未完成 |
| 社区报告 | 有用户结果，但维护者尚未复核完整证据 |
| 失败 | 在明确环境中稳定复现失败，已记录限制或 Issue |
| 未验证 | 没有证据；不能写成“支持” |

验证结论绑定具体应用版本、操作系统、驱动、芯片/板卡和参数，不自动外推到同系列芯片、另一驱动或另一平台。

## 已验证设备

当前为空。清单可从一份满足证据门槛的设备报告开始；首个公开 Beta 仍须在 Windows 10/11 x64 上使用至少一套
真实开发板或 USB 串口设备完成核心连接、双向收发、拔插和重连验收。两种以上芯片、流控、DTR/RTS、
CTS/DSR/RI/DCD（CD）和长稳结果用于扩大兼容声明，不得从首套设备结果外推。

计划优先覆盖的类别仅用于安排测试，不是兼容声明：

- USB CDC ACM 类设备。
- WCH CH34x 类适配器。
- Silicon Labs CP210x 类适配器。
- FTDI FT232 类适配器。

## 能力维度

每条设备记录按能力分别给出通过、失败或未验证，不能用一次“能打开端口”代替全部结论：

| 维度 | 最低证据 |
| --- | --- |
| 枚举 | 冷启动和热插拔后均出现；记录端口类型与 VID/PID |
| 连接 | 参数正确时可连接，非法配置或端口占用时有确定反馈 |
| RX/TX | 已知 payload 双向校验，记录字节数、速率、时长和错误数 |
| 重复连接 | 至少 10 次连接/断开，无残留占用或僵死 worker |
| 拔插 | 至少 5 次连接中拔出/重新插入，状态和再次连接正确 |
| 自动重连 | 仅强 USB 身份；验证跨端口名恢复、取消和重试耗尽 |
| 软件流控 | 使用能产生 XON/XOFF 的对端独立验证，不从“可发送”推断 |
| 硬件流控 | 使用实际 RTS/CTS 接线和足够负载验证背压 |
| DTR/RTS | 用示波器、逻辑分析仪或已知目标行为确认电平变化 |
| CTS/DSR/RI/DCD | 用可控夹具分别验证有效、无效和驱动不可读；RI 脉冲保持至少 400 ms |
| 高波特率 | 只列实际测试值、负载、时长和校验结果 |
| Modbus RTU | 记录 RS-485 适配器、终端电阻/偏置、回显、半双工转向、站号、功能码、超时与原始 TX/RX |
| 长稳 | 目标为至少 8 小时；记录吞吐、内存、丢帧和文件完整性 |
| 数据任务 | 分别记录 VUCAP、数值 CSV、回放和导出结果 |

## 必填证据

一条可进入清单的记录必须包含：

- 日期，Vofa-Ultra 版本/commit，正式包、候选包或开发构建类型。
- Windows 10/11 版本、系统内部版本和 x64 架构。
- 适配器芯片与板卡型号、USB VID/PID、驱动名称和版本。
- 只记录是否存在非空唯一序列号，不公开序列号值。
- 端口类型及波特率、数据位、校验、停止位、流控、DTR、RTS，以及四路输入线的夹具状态。
- 目标固件或测试夹具版本、协议和测试 payload 的公开生成规则。
- 枚举、连接、RX、TX、重复连接、拔插、自动重连、输出控制线、输入握手线和数据任务的逐项结果。
- 测试时长、吞吐/波特率、重复次数、字节数、校验方式和错误计数。
- 稳定错误码、脱敏诊断、关联 Issue/PR 或受控测试记录链接。
- 总结为已验证、部分验证、社区报告或失败，并列出所有未验证项和已知限制。

禁止提交完整 USB 序列号、端口绝对路径、用户名、业务载荷、设备密钥、网络凭据或签名材料。VID/PID 不是秘密，
但仍应与其他字段分开检查，避免旁路泄露设备身份。

## 建议测试流程

1. 校验安装包 SHA-256，记录版本和系统环境。
2. 关闭其他串口程序，连接已知测试夹具，完成基线枚举和参数核对。
3. 用确定性 payload 依次校验 RX、TX、TEXT/HEX 显示和 FireWater/JustFloat/Raw 所需路径。
4. 若验证 Modbus RTU，使用真实 RS-485 总线分别记录单播读写、广播、异常、超时、取消、本地回显和转向时序。
5. 执行重复连接和连接中拔插；符合强身份条件时再启用自动重连并验证取消。
6. 使用合适硬件分别验证软件/硬件流控、DTR、RTS 和 CTS/DSR/RI/DCD。输入线需分别记录接线或信号源，以及
   “有效”“无效”或“不可用”；RI 使用持续至少 400 ms 的脉冲。更短脉冲需用逻辑分析仪验证，不能作为应用验收。
7. 运行持续采集，检查终端、解析健康、波形、VUCAP footer、回放和导出统计。
8. 导出脱敏诊断，核对没有端口名、序列号、绝对路径或收发 payload。
9. 将证据附到[硬件兼容性报告](../.github/ISSUE_TEMPLATE/hardware_report.yml) Issue；维护者复核后再更新本清单。
