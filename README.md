# Vofa-Ultra

面向嵌入式调试与实时数据采集的现代化跨平台串口工作台。

Vofa-Ultra 学习 VOFA+ 与
[vofa-NEXT](https://github.com/Horldsence/vofa-NEXT) 的产品思路，但采用独立实现。项目优先保证串口
生命周期可靠、数据链路可诊断、内存边界明确，并在基础收发稳定之后再引入高级编排能力。

> 当前代码是可运行的 v0.1.0 预发布候选，并已包含路线图中完成验收的 v0.2 / v0.3 能力。项目暂未启用
> GitHub Actions；构建、测试和候选包生成均由维护者在本地手动执行，依赖更新提醒仍由 Dependabot 提供。尚未发布经过签名和完整硬件验证的稳定版本。

## 当前能力

- 冷启动、连接面板打开和窗口回到前台时轻量刷新串口列表，展示厂商、产品与 VID:PID 但不显示完整序列号；
  同时支持配置波特率、数据位、校验位、停止位和流控，连接后可动态切换 DTR / RTS，并只读监视
  CTS / DSR / RI / DCD（CD）。
- 后台串口线程负责收发；连接生命周期串行化，TX 队列、单次发送和所有 UI 缓存均有硬上限。
- 文本 / HEX 收发、TX 的 LF / CR / CRLF 行尾、绝对/缓存相对/可见记录间隔时间、终端字面量搜索、RX/TX
  过滤、吞吐统计，以及全部缓存或当前筛选视图日志导出。
- RX 终端可按原始读取块或文本行记录；文本行支持 LF / CRLF / CR，TEXT 可选 UTF-8、GB18030 或
  Windows-1252，并正确聚合跨读取块的多字节字符。
- 会话级有界命令历史、安全命令变量、ASCII 快查、独立校验与字节/数值互转、工作区级自动校验尾，以及可取消
  周期发送。
- 桌面串口原始文件流式发送，提供显式开始、精确进度、取消和发送工作流互斥，不把整个文件载入内存。
- 工作区级命名快捷命令保留原始模板、TEXT/HEX 格式和行尾；载入只回填草稿，不会自动发送。
- Modbus RTU 常用读写构帧与单事务主站，支持总线静默、响应超时/取消、异常响应和会话级结构化结果。
- 默认关闭的有界 RX 自动应答，支持 TEXT/HEX 字节触发、跨分片匹配、冷却和手动发送优先。
- FireWater 文本帧与 JustFloat 浮点帧增量解析，使用静态内置注册表和合规夹具验证任意分包与错误恢复。
- 桌面端实验性 `.vux` Wasm 协议解析扩展，零 import、显式实时 RX 授权、独立通道和有界故障隔离。
- FireWater / JustFloat 解析健康度，按稳定原因统计成功、丢弃与重同步，并区分实时和回放数据流。
- FireWater / JustFloat 工作区级基础通道别名、单位与颜色，按协议隔离并即时投影到侧栏、波形、触发、测量和
  姿态菜单，不改写 parser 原名或数值。
- uPlot 实时波形、最多 16 个基础通道与 16 个派生通道、共享/独立自动量程、固定 Y 量程、时间窗切换、框选挂起
  跟随、一键回到实时、上升/下降沿单次触发、独立暂停、双游标测量和 A/B 区间统计。
- 按需加载的实时通道监视，直接分组显示基础、派生与扩展通道，并以最近 256 个点计算当前值、变化量、极值、
  均值、RMS 和样本数；本地冻结不停止采集。
- 可选的有界数据处理 DAG，提供缩放偏移、限幅、滤波、双路运算、帧内字节/数值转换和独立输出路由。
- 按需加载的 Three.js 3D 姿态视图，支持 Euler 角度/弧度、四元数、两套坐标系、帧一致映射、冻结与归零。
- 内置模拟数据源，无串口硬件也能贯通协议、波形、终端和发送流程。
- 终端虚拟列表、三种时间基准、匹配高亮、上滚临时挂起跟随、一键回到最新、明暗主题、桌面可调分栏与专注
  模式，以及窄屏安全布局。
- 命名工作区保存、应用、另存、删除与 JSON 导入导出；切换前安全断开，但不会自动连接设备。
- `.vucap` v2 原始会话录制，Rust 独立 writer、有界背压、RX / TX 与持久命名标记共用单调时间线，并可与
  实时数值 CSV 共用会话级记录目录。
- FireWater / JustFloat 基础与派生数值通道实时 CSV，动态通道长表、双层有界队列和原子文件提交。
- `.vucap` v1/v2 有界流式回放，支持五档倍速、seek、持久标记定位和未完成文件有效前缀。
- `.vucap` 流式导出为 CSV、JSONL 或单向原始二进制，支持方向过滤、进度、取消和失败恢复。
- 可取消的串口自动重连：用 VID、PID 与非空 USB 序列号识别原设备，跨端口名恢复且不猜测歧义设备。
- 256 条有界恢复事件与 128 KiB 脱敏诊断导出，不包含端口名、序列号、原始错误或收发载荷。
- Vitest 单元 / 组件测试、Playwright 浏览器验收、桌面构建检查和按目标生成无签名候选包的本地命令。
- 每目标 CycloneDX 1.6、许可证允许策略、第三方 notices、应用内嵌资源和完整发布文件校验。
- 机器可读的配置、VUCAP 与协议 wire ID 兼容矩阵，以及前端/Rust 双侧防漂移门禁。

## 快速开始

### 浏览器预览

浏览器预览只能使用模拟数据源，适合开发界面与协议逻辑。

```bash
pnpm install
pnpm dev
```

打开 <http://127.0.0.1:1420>，点击“启动模拟”即可看到三通道实时数据。

### 桌面应用

需要 Node.js 22、pnpm 11、Rust 1.88.0 或更高版本，以及
[Tauri 2 平台依赖](https://v2.tauri.app/start/prerequisites/)。

```bash
pnpm install
pnpm tauri dev
```

仓库已提交 `src-tauri/Cargo.lock`，桌面构建应使用锁定依赖。正式发布前仍需在目标平台完成真实串口连接、
收发、拔插和重连验证。

### 本地无签名候选包

项目当前不会在 push、PR 或版本标签上自动构建和发布。需要候选包时，维护者在对应目标系统手动运行以下命令。
这些产物未经代码签名、公证、跨平台安装和真实串口验证，不应作为稳定版本发布。供应链材料的生成范围见
[供应链发布说明](docs/supply-chain.md)；人工发布步骤见[发布流程](docs/release-process.md)。

```bash
pnpm check:package
# Windows
pnpm supply-chain:check x86_64-pc-windows-msvc
pnpm tauri build --ci --no-sign --target x86_64-pc-windows-msvc --bundles "msi,nsis"
pnpm package:collect windows x86_64-pc-windows-msvc
# macOS
pnpm tauri build --ci --no-sign --target x86_64-apple-darwin --bundles dmg
pnpm package:collect macos x86_64-apple-darwin
# Linux
pnpm tauri build --ci --no-sign --target x86_64-unknown-linux-gnu --bundles "deb,appimage"
pnpm package:collect linux x86_64-unknown-linux-gnu
```

## 协议输入

FireWater 每行是一帧，支持纯数值和命名通道：

```text
1.25,-2,3
temperature:23.5,voltage:3.30
yaw=1.234 pitch=0.567 cur=0.8
```

命名字段在同一帧中统一使用 `:` 或 `=`；重复分隔符、空标签、空值、逗号空字段和混用形式都会被拒绝并计入
解析健康度。

JustFloat 每帧由若干个小端序 `float32` 组成，以 `00 00 80 7F` 结尾。Raw Data 模式只进入终端，
不生成波形通道。两种结构化协议的解析结果限制为 1 到 16 个有限数值；仓库内新增解析器须遵循
[内置协议贡献契约](docs/protocols.md)。

桌面端另提供实验性的 [`vux-wasm-v1`](docs/extensions.md) 实时附加解析器。它异步消费 RX 副本并输出独立
`extension:*` 波形，不替换当前内置协议，也不进入基础 `rxFrames`、协议健康度、处理图、姿态、数值日志、
VUCAP 或回放。需要只观察扩展结果时可把基础协议选为 Raw；这仍不是稳定插件 ABI 或完整第三方生态。

已发布内置协议 wire ID 采用追加策略并保持原含义；稳定范围仅覆盖持久标识和文档化解析行为。实验性扩展的
版本状态和弃用规则见[兼容性与弃用政策](docs/compatibility.md)。

“通道”面板会显示当前结构化协议的成功帧、丢弃帧、重同步次数和最近失败原因。统计在波形或终端暂停时仍继续，
实时采集与回放相互隔离；切换协议、数据源、连接流、工作区或回放时间线会重置对应统计。清空统计不会丢弃正在
等待完成的半帧。诊断只保留固定原因码和计数，不保存被拒绝的原始载荷；Raw Data 明确显示为“不适用”。

基础通道行的编辑按钮可为当前 FireWater 或 JustFloat 协议设置可选别名、单位和颜色；同一个 `channel-0` 在两种
协议中分别保存，回放使用捕获文件的协议配置。别名和颜色会进入界面展示，单位会附加到实时读数、触发阈值和
测量值，但不会换算数值。parser 原名、稳定通道 ID、处理图、姿态自动映射、数值 CSV、VUCAP 和协议健康度保持
原语义；恢复默认会删除该通道的展示覆盖。Raw、派生和扩展通道没有此编辑入口。

## 有界数据处理图

“处理”面板使用列表式节点编辑器建立静态 DAG。`input` 读取固定基础通道，之后可串联 `affine`、`clamp`、
`ema`、`moving_average`、双输入 `math`、`bytes_to_number` 和 `number_to_byte`，最后由 `output` 发布稳定 ID 为
`derived:<output-id>` 的派生通道。
基础 `channel-0..15` 的数据层 ID 和 parser 原名不会被替换或重命名；展示别名只作用于界面。派生通道可单独
显隐，并与基础通道一起进入波形视图。

`bytes_to_number` 按选定类型读取同一个完整解析帧中的 1/2/4/8 个上游字节标量，并按显式 LE/BE 解码一个
数值。每个字节必须是 `0..255` 的整数，输入不足、越界、非整数或非有限结果只让当前帧产生 gap，绝不跨帧
拼接。`number_to_byte` 把一个有限标量编码后按索引输出一个 `u8`；需要多个字节时显式建立多个节点。两类节点
都不会读取原始 RX、生成 TX 或隐式发送。

处理图最多 64 个节点和 16 个输出；单个移动平均窗口最多 256，总窗口容量最多 8,192 个数值，单批最多执行
1,000,000 次节点求值。配置时拒绝重复 ID、未知引用、自引用、循环、非法参数和未知字段。图只接受固定节点和
数值参数，不支持表达式、脚本、`eval`、动态代码或第三方运行时。

实时采集与回放各自持有独立滤波状态。暂停波形时处理状态继续推进，只停止追加显示点；切换协议、数据源、
工作区或回放时间线会在对应边界重置状态。除零、缺失输入和非有限结果只在当前样本产生 gap；意外异常或预算
超限会熔断处理层，原始 RX、终端、录制、统计和基础波形继续工作，用户可在面板中显式重试。

## 工作台布局

桌面工作区可拖动波形/监视/姿态与终端之间的水平分隔条；分隔条支持 `ArrowUp`、`ArrowDown`、`Home`、`End`，双击
恢复默认比例。标题栏的三段式布局控件可临时专注当前主视图、恢复分栏或专注终端。分栏比例单独保存在本机，
不写入工作区或导出文件；专注状态不会跨重启保留。

宽度不超过 720 px 时隐藏桌面布局控件并固定显示主视图和终端，不继承桌面专注状态。宽度不超过 520 px 时
终端保留完整发送操作高度；短屏在工作区内部滚动，固定底部导航不会遮挡发送按钮。

## 终端筛选与导出

终端最多保留 800 条记录。搜索按当前 TEXT/HEX 已显示负载执行大小写不敏感的字面量匹配，并可叠加 RX/TX
方向筛选；筛选只改变当前视图，不修改缓存或数据链路。

下载菜单可选择“全部缓存”或“当前视图”。当前视图严格使用此刻的显示模式、搜索和方向筛选，并保持记录顺序；
未启用筛选或零结果时该项禁用。两种范围都写入 UTF-8 `.log`，每行依次为绝对 ISO 时间、方向、字节数和
payload。payload 中的反斜杠、Tab、CR 和 LF 会转义为单行文本，因此 REL/ΔT 等视图时间不会改变导出时间。
终端日志仍受 800 条缓存及单条展示上限约束，无损原始字节应使用 `.vucap` 录制。

## 波形浏览、单次触发与双游标测量

通道条可在“共享”和“独立”量程之间切换。共享模式默认让所有可见通道使用同一纵轴，适合直接比较相同单位和
相近数量级的数据；独立模式让每个通道分别自适应，只显示焦点通道对应的纵轴，适合同时观察转速、电流和温度等
混合量级数据。焦点通道可在通道条中选择，开启或切换测量通道时会同步，测量游标始终按被测通道的量程映射。

量程按钮可把当前共享纵轴或独立焦点通道固定到两个有限数值之间，且严格要求下限小于上限；再次打开可一键恢复
自动量程。共享范围和各通道独立范围在当前视图内分别保留，改变时间窗、暂停或测量不会清除。隐藏焦点通道时会
回退到下一个可见通道；通道被移除后会同步删除其范围，全部隐藏后图表保持安全空态。

量程模式、焦点和固定范围只属于当前波形视图，不写入工作区，也不改变采集、解析、触发阈值、数值日志或通道
原始值。清空波形，以及切换协议、数据源、处理图、工作区、回放会话或时间线会恢复自动量程，避免旧物理范围套用
到新的数据流。

在实时波形中沿 X 轴框选可放大历史区间。有效缩放会挂起视口自动跟随并显示“回到实时波形”按钮，但 `LIVE`
状态、RX、协议解析、处理、终端、统计、录制和数值日志都继续运行。挂起期间图表继续接收 Store 已保留的有界
环形数据，而不是只接收向前移动的当前时间窗；点击按钮会重新裁剪到所选时间窗并立即适配最新数据。

视口跟随挂起只属于当前组件，不写入工作区或浏览器持久化。改变时间窗、显式暂停/继续、进入或退出测量，以及
清空波形、切换协议、数据源、处理图、工作区、回放会话或时间线都会恢复实时跟随；最旧数据仍受每通道
2,000 点环形上限约束。

波形工具栏的准星按钮提供实时单次触发。选择一个基础或派生通道、上升沿或下降沿和有限阈值后布防；布防后的
第一个新样本只建立基线。当前 5 / 15 / 30 / 60 秒窗口同时作为总捕获窗，越过阈值后再采集半个窗口，到达
截止时间的整个解析批次会先写入波形，再冻结视图并以 `T` 标线标出触发时刻。冻结后 RX、协议解析、处理、姿态、
终端、统计、VUCAP 和数值日志继续运行；“重新布防”会恢复实时追加并开始下一次单次捕获。

单次触发只适用于已连接的实时串口或模拟器，不支持回放和异步 `extension:*` 通道。触发状态是会话运行态，不写入
工作区或浏览器持久化。手动暂停/继续、测量、框选历史、清图、改变时间窗、协议、来源、处理图、连接代次、
工作区或回放边界都会解除当前触发；派生源处理图熔断时同样解除，避免用失效样本继续判边沿。

波形工具栏的直尺按钮会冻结当前波形视口并建立 A / B 两个采样游标。可选择任一基础或派生通道，通过图中点击、
触摸滑杆或键盘移动游标；游标始终吸附真实采样时间，并显示 `tA`、`tB`、`Δt`、`1/Δt`、`yA`、`yB` 和 `Δy`。
同一测量条按 A/B 闭区间统计被测通道的真实有限样本，显示样本数、最小值、最大值、均值、RMS 和峰峰值；单样本
区间的峰峰值为 0。基础通道配置单位后，实时值、触发阈值标题、游标幅值和区间统计会显示该单位，但仍按原始数值
计算和比较。
测量期间 RX、协议解析、处理运行时、终端、统计和录制继续运行。关闭测量后，仅当波形原本处于实时状态时恢复
追加；用户在测量前主动暂停的波形仍保持暂停。

测量属于当前视图的临时状态，不写入工作区或浏览器持久化。清空波形，以及切换协议、数据源、处理图、工作区、
回放会话或回放时间线时会自动结束测量，避免游标继续引用已经失效的数据。

## 实时通道监视

“监视”把基础、处理图派生和扩展通道直接绑定到紧凑表格，不需要创建显示节点或连线。默认只列出可见通道，也可
切换为全部通道；每行显示当前值、相邻有效样本变化量、最小值、最大值、均值、RMS 和有效样本数，并沿用基础
通道的别名、单位与颜色。每个通道只扫描源序列末尾最多 256 个条目，非有限值不会进入统计。

冻结按钮只保存当前面板快照，RX、parser、处理、扩展、波形、终端、录制与回放继续运行；再次点击立即显示最新
统计。清空波形，以及切换协议、来源、处理图、工作区、回放会话或时间线时会自动解除旧快照。监视范围和冻结
状态不写入工作区。窄屏保留通道、当前值、变化量和样本数，隐藏次要统计列，不产生页面级横向滚动。

## 3D 姿态视图

工作区顶部可在波形、监视与姿态视图之间切换。姿态映射可选择基础或派生通道；Euler 模式读取 Roll、Pitch、Yaw，
接受 degrees 或 radians，并固定使用内禀 ZYX 旋转顺序。Quaternion 模式固定读取 W、X、Y、Z，输入会先归一化；
非有限值和模长过小的四元数不会进入渲染器。坐标约定可选 ENU 世界坐标 / FLU 机体坐标，或 NED 世界坐标 /
FRD 机体坐标，再统一变换到 Three.js 场景。

姿态通道菜单显示当前协议的基础通道别名，自动映射仍优先匹配 parser 原名，并只把别名作为次级候选；因此把
`roll` 展示为“横滚角”不会破坏已有自动映射。

姿态不是从各通道最后值临时拼接。协议帧与处理图输出携带同一批次内的 `frameIndex`，只有来自同一个完整解析帧、
且时间戳一致的映射值才会组成姿态；即使两个解析帧共享时间戳也不会互相混用。实时采集和历史回放复用同一条
提取路径，成功 seek、停止后重播、切换回放时间线、协议、数据源、处理图或工作区都会使旧姿态失效。

冻结按钮只保留当前显示样本，RX、协议解析、处理图、终端、统计、录制和回放仍继续运行；归零与相机视角复位
同样只属于当前视图，不写入工作区。Three.js 渲染器限制设备像素比，卸载或切换主题/坐标系时释放 GPU 资源；
无法创建 WebGL 上下文时会保留配置和数值读数，并显示明确的“3D 渲染不可用”状态。

## 工作区配置

工作区保存数据源、协议、串口参数、终端收发格式、命令校验模式、TX 行尾、RX 记录方式、接收行尾与文本编码、
时间窗、自动滚动、通道显隐、按协议隔离的基础通道展示配置、处理图、姿态映射、自动应答规则和命名快捷命令。
连接状态、处理运行时、波形触发状态、监视冻结快照、最新/冻结姿态、姿态归零、实时波形、终端记录和统计不会
进入配置文件。
应用工作区会先
断开当前数据源、清空运行数据并恢复显示设置，不会自动连接保存的设备。

导出文件使用带格式标识的 v11 JSON schema，单文件上限为 2 MiB，确保控制字节经过最坏 JSON 转义后仍可自导入。
导入时会严格校验字段、图拓扑、姿态通道、展示配置、自动规则、快捷命令和参数范围；严格的 v1-v10 文件会迁移到
v11，并把命令校验模式补为“无”。v1-v6 的 RX 记录方式默认迁移为按读取块，接收行尾默认为 LF；v1-v7 的
接收文本编码默认为 UTF-8，v6 的 CR-only 发送语义保持不变。同名配置会创建带编号的新副本，不会
覆盖或自动应用现有工作区。浏览器预览可导入串口工作区，但运行时会安全降级到模拟器；原始串口配置仍保留在
命名快照中。工作区文件、本地状态和未来版本的确定行为见[兼容性与弃用政策](docs/compatibility.md)。

## 会话录制

Tauri 桌面应用连接数据源后，可在“记录”面板开始录制。原生串口 RX 和每次成功写入设备的 TX 字节分片会
直接进入 Rust writer；Tauri 模拟器通过有界 IPC 队列写入同一格式。停止、断开或切换工作区时会先完成文件
收尾。原始录制和实时数值 CSV 共用“记录目录”：默认保存到系统下载目录的 `Vofa-Ultra`，也可在开始前选择
现有文件夹。自定义目录只在本次应用运行期间保留，不进入工作区或本地持久化；取消选择不改变当前状态。

捕获文件保存起始时间、数据源、协议、串口参数，以及带相对单调微秒时间的原始记录和命名标记。数据与标记进入
同一个有界 writer 队列；Tauri 模拟器还通过前端有界 FIFO 串行提交，文件顺序就是时间线顺序。每个文件最多保存
512 个标记。正常文件以带记录、字节和标记计数的 footer 结束；磁盘错误或队列溢出会中止录制并保留可诊断的
未完成文件，不会静默丢弃数据或拖慢串口 worker。writer 只产生 v2，reader 继续兼容 v1。完整 wire contract 见
[VUCAP 捕获文件格式](docs/capture-format.md)。浏览器预览不开放真实文件录制。

Rust 只接受现有绝对目录；显式目录不可用时会明确失败，不会回退到其他位置。文件名仍由应用生成，并在启动时
避让已有 `.vucap`、`.csv` 和 `.csv.part`；目录选择不会扩大为指定或覆盖任意文件名。

## 实时数值记录

桌面应用连接 FireWater 或 JustFloat 数据源后，可在“记录”面板的“数值”标签独立启动 CSV 记录，也可与
`.vucap` 原始捕获并行运行。记录入口直接接在协议解析和可选处理图之后、波形暂停分支之前；因此基础通道不
依赖处理图，派生通道按实际输出记录，暂停或清空波形不会造成 CSV 断档。Raw Data 和历史回放不产生实时数值
日志。

CSV 使用固定长表表头，每个有限基础值或派生值占一行：

```text
sample_index,timestamp_unix_us,elapsed_us,channel_kind,channel_id,channel_name,value
```

动态出现的通道不会改变 schema。`timestamp_unix_us` 是协议帧完成时的 Unix 微秒时间，`elapsed_us` 是 Rust
接受该批次时相对日志启动的单调微秒时间；同一输入批次可共享后者，可靠总顺序由 `sample_index` 给出。文件
使用 UTF-8 BOM、CRLF 和 RFC 4180 文本转义，并防止通道字段触发电子表格公式。

前端队列限制为 1 MiB 和 2,048 条样本，Rust writer 再限制为 64 批、4 MiB 和 4,096 条样本；任一边界溢出或
磁盘错误都会只中止数值日志，不中断串口或并行的 `.vucap` 捕获。写入期间文件后缀为 `.csv.part`，正常刷新和
同步后无覆盖提交为 `.csv`；同名最终文件、提交失败或 I/O 故障会保留可诊断 `.part`，后者末行可能不完整。详细契约见
[实时数值 CSV](docs/capture-format.md#实时数值-csv)。

## 会话回放

桌面应用可从“记录”面板的“回放”标签打开任意 `.vucap`，也可直接回放最近一次录制。选择文件后，应用会先
完成仍在进行的录制并断开实时数据源；取消文件选择不会改变当前连接、录制或回放会话。回放使用捕获文件中的
协议和历史时间戳，但不会修改或弄脏当前工作区配置。

后端扫描时建立最多 65,536 项、约 2 MiB 的自压缩稀疏索引；播放阶段仍只保留 reader、一个预读 record 和一个
待确认批次。每批受 128 KiB、128 条记录和 16 ms 捕获跨度约束，前端完成同步入库后才 ACK 下一批。正常 footer
会显示完整状态；缺少 footer 或尾部截断时仍可回放已验证的完整记录前缀，其他格式损坏会被拒绝。

Raw Data、FireWater 和 JustFloat 回放均可在就绪、暂停或完成状态拖动时间轴定位。拖动只更新本地草稿，松手或
键盘提交时才发送一次 IPC；后端异步定位并用 generation 隔离旧命令与 ACK，成功切换时间线后再清空旧波形和
终端。定位期间可停止或关闭。

Raw Data 吸附 record 边界。FireWater 以 RX 换行、JustFloat 以完整 `00 00 80 7F` 帧尾作为安全同步点；TX 交错
不改变 RX 同步状态。后端只把已知同步的 record 末端加入结构化稀疏索引，并在定位时丢弃目标处可能残缺的第一
个单元，从协议边界后的 record 内偏移继续回放。若请求位置本身安全则不会额外跳帧；否则时间轴会显示后端返回
的实际吸附时间。找不到后续同步点时定位到已验证末尾，不会把半帧交给重置后的前端 parser。

回放支持 `0.25× / 0.5× / 1× / 2× / 4×` 五档倍速，并可在就绪、播放、暂停和完成状态切换。播放中切速
会保持当前代次、待确认批次和可见进度连续；暂停、定位、停止和完成后重播保留当前倍速，打开新文件或关闭
回放后恢复 `1×`。倍速只属于当前会话，不写入 `.vucap` 或工作区。

打开 v2 捕获时，扫描阶段最多收集 512 个持久标记，回放时间轴显示刻度和有界列表。就绪、暂停或完成状态可
点击标记定位；播放或正在 seek 时会禁用定位。标记使用与 RX / TX 相同的单调微秒时间线，但不会进入数据批次或
改变 ACK 协议；v1 文件正常显示为空标记集合。

## 捕获文件导出

桌面应用可在“记录”面板的“导出”标签选择任意 `.vucap` 或最近一次录制，并按 RX、TX 或双向记录导出。CSV
每条记录保存源序号、相对/绝对微秒时间、方向、长度和无损十六进制 payload；JSONL 额外保存捕获元数据、
Base64 payload 和完成摘要。原始二进制会按记录顺序拼接所选方向的 payload，因此必须明确选择 RX 或 TX，
不会把双向数据无提示地混为一个字节流。

VUCAP v2 导出为 JSONL 时会按源文件顺序保留 record 与 marker，summary 同时给出标记计数；方向过滤只过滤
RX / TX record，不会删除标记。CSV 和原始二进制明确跳过标记，继续保持纯数据契约。

导出由单个 Rust worker 流式完成，前端只接收进度状态，不承载文件内容。输出先写入目标同目录的唯一临时文件，
刷新并同步后再提交；取消、格式损坏、源文件变化或磁盘错误不会留下半成品，也不会破坏已有目标。不完整捕获
默认拒绝，只有显式启用“允许导出不完整文件的有效前缀”后才会提交已验证记录并保留警告。浏览器预览不开放
源文件或保存对话框。

## 串口恢复与诊断

自动重连默认关闭，只在当前应用运行期间由用户显式启用，不写入工作区或持久化存储。一次手动连接成功后，
应用冻结设备的 USB VID、PID 和非空序列号；意外读写故障会先完成正在录制的捕获文件，再按
`0 / 0.5 / 1 / 2 / 4 / 8 / 16 / 30 / 30 / 30` 秒最多尝试十次。设备改用新的端口名仍可恢复；身份字段
缺失或出现多个相同候选时会停止并要求用户选择，不按旧端口名或同型号猜测。

等待、扫描和连接阶段都可立即取消。后端 generation 门禁会丢弃取消后迟到的打开结果，前端 epoch 同时隔离
迟到的端口枚举和连接 Promise。恢复成功会重置协议流式残片与文本解码边界、重新开始传输统计，但保留已有
波形和终端历史。连接面板可导出有界 JSON 诊断；报告只包含稳定错误码、相对时间、计数和脱敏串口参数。

## 原始文件发送

Tauri 桌面应用连接真实串口后，可从发送栏的文件按钮选择任意本机文件。选择文件只建立本次发送草稿，必须再次
点击“开始发送”才会读取和写入；完整路径不会进入前端 Store、工作区、命令历史或诊断报告。后端以 64 KiB
有界缓冲读取文件，拆成最多 4 KiB 的串口写块，并限制单轮 worker 写入预算为 32 KiB，不会随文件大小增长内存。

进度按串口驱动实际接受的字节累计，全部字节写入后还必须成功 `flush()` 才算完成。成功写入字节按有界批次作为
TX 进入终端与吞吐统计，VUCAP 则按底层每次成功写入的实际分片记录。取消会停止后续读取和写入，但串口驱动已经
缓冲的字节仍可能继续发出；断连、换源、切换工作区、进入回放和运行时卸载都会取消当前任务。

同一时间只允许一个文件发送任务，并与手动发送、周期发送、RX 自动应答和 Modbus RTU 事务严格互斥。当前能力
只是无封装的原始字节流，不应用 TEXT/HEX 转换、命令变量、工作区命令校验或行尾，也不提供协议分包、接收文件、
续传、自动重试、
校验确认或限速；需要设备侧确认与可靠恢复时，应在原始串口链路之上使用明确的传输协议。

## 命令模板、历史与周期发送

发送内容支持不执行代码的命令变量。TEXT 模式可直接使用 `${seq}`、`${unix_ms}`、`${unix_s}`、`${iso_utc}` 和
`${task_unix_ms}`；HEX 模式必须指定定宽格式，例如 `${seq:u16le}` 或 `${unix_ms:u64be}`。TEXT 中 `$$`
表示字面量 `$`。模板只经过一次线性扫描，不支持属性、函数、运算、嵌套、环境变量、随机数或 RX / 通道引用。

```text
SET,${seq},${unix_ms}
AA 55 ${seq:u16le} ${task_unix_ms:u64be}
```

发送栏可在“无”、CRC-16/MODBUS 低/高字节在前、CRC-32 低/高字节在前、XOR-8 和 SUM-8 之间选择自动校验尾。
每次发送都按“模板展开 payload -> 原始校验字节 -> TX 行尾”构造完整帧；校验只覆盖展开后的 payload，
不覆盖行尾。
该选择属于当前工作区，并同时用于手动和周期发送。

原始模板最多 256 KiB、包含最多 256 个变量，单个变量 token 最多 64 个字符；展开 payload、校验尾与行尾合计
仍受 64 KiB 单次发送上限约束。手动发送的序号固定为 1；周期任务从 1 开始，只有成功发送后才推进。
`unix_ms` 每次派发重新
采样，`task_unix_ms` 在任务启动时冻结。完整语法与失败语义见
[安全命令模板](docs/command-templates.md)。

发送栏的书签按钮管理当前工作区的命名快捷命令。最多保存 32 条，名称最多 64 个字符，全部原始模板合计不超过
128 KiB；列表顺序也是持久化和导出顺序。保存会原样保留模板、TEXT/HEX 格式和行尾，但不保存校验模式；载入只
替换这些草稿字段，不展开变量、不产生 TX、历史或诊断事件。用户仍需点击“发送”或启动周期任务，并使用当前工作区
的校验模式。快捷命令会写入本机工作区状态和导出的
工作区 JSON，因此不应保存密码、令牌或其他不适合持久化和分享的敏感内容。

每次被发送队列成功接受的手动或周期命令都会进入当前应用会话的历史，保存原始 payload、TEXT / HEX 格式、
校验模式和行尾。含变量的历史保存原始模板和最近一次展开字节数，点击恢复后会重新求值；真实发送字节由 TX
终端与 `.vucap` 记录。只有 payload、格式、校验模式和行尾都相同的连续命令才会合并计数；历史同时限制为最多
100 条和
256 KiB payload，超限从最旧项淘汰。
历史、输入草稿和任务状态不会写入工作区、`localStorage` 或诊断报告，可从终端发送栏单独清空。输入框在第一行
按上键浏览旧命令，在最后一行按下键返回；回到历史末尾时会恢复浏览前的完整草稿、格式、校验模式和行尾。

周期发送支持 20 ms 到 24 小时的非实时整数间隔，以及 1 到 100,000 次或持续模式。启动时会编译并冻结模板、
格式、校验模式和行尾；每次派发使用显式序号与时间上下文重新生成 payload，再计算该轮校验尾。之后编辑输入框或
切换工作区校验模式不会改变运行任务。调度器只允许
一个 `send()` 在途，上一次完成后才开始下一次间隔，不会用 `setInterval` 追赶遗漏周期或制造突发队列。用户
停止、断开或故障、自动恢复开始、切换数据源或工作区、打开回放和运行时卸载都会取消后续发送；重连后不会自动
恢复旧任务。队列满、非法 HEX、变量溢出或其他发送失败会明确停止任务。

### 字节/数值互转

命令参考弹层的“转换”页是独立诊断工具。它支持 `u8/i8/u16/i16/u32/i32/f32/f64`，并对
多字节类型显式选择 LE/BE。HEX 解码要求完整字节且按选定类型对齐；数值编码严格拒绝空项、
非整数、整数越界、`NaN` / `Infinity` 和浮点溢出。`f32` 结果会回读实际 IEEE 754 值。

输入文本最多 256 KiB，参与转换的字节数据最多 64 KiB，单个数值 token 最多 128 个字符。该页只在本地转换和
显式复制结果，不读取实时 RX、不改写处理图或发送草稿，也不会产生 TX。处理图中的转换由独立的固定节点配置，
不会自动读取或同步该弹层的输入。

### Modbus RTU 单事务主站

发送栏的积木按钮打开 Modbus RTU 构帧器，覆盖 `01/02/03/04/05/06/0F/10` 八种常用读写请求。站号限制为
`0..247`，地址使用协议原始的 0-based `0..65535`；读位、读寄存器、写多线圈和写多寄存器分别遵循
`2000/125/1968/123` 的数量上限，并拒绝越过末地址的范围。多值写入的数量和字节数由值列表推导，不能单独制造
不一致字段。CRC16 通过锁定的成熟实现计算，在线路中按低字节在前附加。

“填入发送框”和“执行事务”是两个独立动作。前者只生成已经包含 Modbus CRC 的规范化 HEX 草稿，并强制无校验尾、
无行尾，不写串口；后者在当前
连接上执行一次请求/响应。桌面后端会再次校验请求和 CRC，等待 RTU `t3.5` 静默窗口，再通过唯一串口 worker
完整写入并 `flush()`；响应超时从此刻开始。解析器支持跨接收分片、前置无关字节、正常响应、异常响应，以及
CRC、字节数和写回显不匹配错误。站号 `0` 只允许写功能码，广播写在发送完成后结束，不等待响应。

同一时间只允许一个 Modbus 事务，响应超时可设为 `100..60000 ms`。事务运行时会拒绝手工、周期和自动应答发送；
取消、断连、重连、切换来源/工作区和运行时卸载都会结束当前事务。若请求已经发出后再取消，界面会明确提示写
操作可能已经由设备执行。原始 TX/RX 仍完整进入终端、统计和 VUCAP，结构化结果单独保留最近 32 条会话记录，
不会写入工作区或手工命令历史。

当前范围不包含轮询器、寄存器地图、自动重试或 Modbus TCP，也不会注册为波形协议。真实 RS-485 适配器的本地
回显、半双工收发方向切换和设备时序仍须按硬件兼容流程验证。

## RX 自动应答

“自动化”侧栏可保存最多 16 条有序规则。触发器只接受 UTF-8 TEXT 或静态 HEX 字节串，按原始实时 RX 匹配，
支持跨接收分片、重叠模式和 `00`；回放使用独立入口，不会触发应答。响应复用安全命令模板和规则自身的行尾，
不应用发送栏的工作区校验模式；自动 TX 会
进入终端、统计和 VUCAP，但不会污染手动命令历史。

每条规则使用 20 ms 到 24 小时的固定冷却。运行时最多保留 32 个含在途项的 FIFO、单批接受 64 次匹配、单次
启用接受 1,000 个应答；任一预算超限、模板渲染或发送失败都会清队列并安全停机。手动发送等待当前自动写入完成
后优先于其余自动项，周期发送与自动应答互斥。规则随工作区保存，启用态、匹配尾、冷却、队列、计数和错误
不持久化；断连、换源、换协议、重连流边界、切工作区、进入回放和应用卸载都会停止运行。

## 质量检查

```bash
pnpm check
pnpm benchmark
pnpm check:package
pnpm supply-chain:check
pnpm test:e2e
pnpm tauri build --ci --no-bundle
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
cargo clippy --locked --manifest-path src-tauri/Cargo.toml --all-targets --all-features -- -D warnings
cargo test --locked --manifest-path src-tauri/Cargo.toml
```

`pnpm check` 会依次执行 ESLint、TypeScript 类型检查、Vitest、工具脚本测试和生产构建。构建会验证姿态视图
保持动态加载、Three.js 不进入首屏静态依赖图；首屏上限为 656 KiB / gzip 202 KiB，姿态模块上限为
650 KiB / gzip 180 KiB。
`pnpm benchmark` 以单 worker 运行固定工作量的协议、处理图、扩展同步分批复制和 2000 点饱和 Store 场景，再严格核对场景集合、
中位数和最少样本数。当前只执行本地基准，结果用于发现明显回退；原始报告和摘要写入
`artifacts/performance/`。方法与预算维护规则见[性能基准](docs/performance.md)。
`package.json` 是界面和诊断报告的版本来源；`pnpm check:package` 使用 `cargo metadata` 核对 npm、Tauri、Cargo
版本、许可证、公开仓库坐标、应用标识与 bundle 元数据。`pnpm supply-chain:check` 按当前 Rust target 验证
npm 生产依赖和 Cargo 正常依赖闭包，未知或不可接受许可证会令检查失败，并用官方严格 Schema 校验 CycloneDX 1.6。
自动化测试会验证模拟数据链路、
Canvas 有效像素、处理图转换链与工作区 v11 往返、自动校验尾顺序与历史恢复、通道展示配置协议隔离、
实时通道监视统计/冻结/窄屏布局、RX 文本编码/文本行任意分包与生命周期边界、实时 RX 自动应答、
快捷命令持久化/零隐式 TX、录制与回放入口权限、
Raw 回放拖动期间零 IPC 且提交时恰好一次定位、播放中切速不换代、有界命令历史、安全变量的 TEXT / HEX 展开与
拒绝边界、周期/自动发送互斥、
390 px 窄屏无页面级
横向溢出、捕获导出入口权限，以及短窗口发送栏可用性；Tauri IPC
模拟还会验证同一 USB 设备从 `COM3` 迁移到 `COM19` 后的自动恢复流程。

姿态数学和组件测试另外固定 degrees/radians 的内禀 ZYX 等价性、W/X/Y/Z 归一化、ENU/FLU 与 NED/FRD
方向、同解析帧组装、无效输入拒绝、自动映射、冻结、归零、视角复位和 WebGL 错误反馈。
